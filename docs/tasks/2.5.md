# 2.5 GPU frustum and Hi-Z occlusion culling in compute

**Goal:** the GPU decides what terrain to draw.
- A compute pass tests every resident cube against the frustum and a hierarchical-Z depth pyramid, skips back-facing directions, and writes the indirect commands that 2.2's `multi_draw_indirect` consumes.
- Culling is two-phase:
  - Draw what was visible last frame.
  - Build the Hi-Z pyramid from that depth.
  - Test everything against the pyramid and draw what was missed.
- So nothing pops in when the camera moves, and caves under the player cost almost nothing.

The CPU no longer touches cubes per frame on this path. The 2.2 CPU-culled path stays as the fallback and as the reference the GPU path is tested against.

## Scope

### Persistent cube metadata (`render/chunks.rs`)

- Every resident cube with a non-empty mesh gets a **slot** in a persistent `cube_meta` storage buffer.
  - Slots come from a free list and are grown like 2.2's buffers. Reuse `Suballocator` with unit-size allocations, or a simple free list.
  - Upload writes the slot, remove frees it, and a re-mesh rewrites it in place.
  - Nothing is rewritten per frame.
- `CubeMeta` (WGSL mirror, 16-byte aligned, with a layout test like `FrameUniforms`'s) holds:
  - `pos: vec3<i32>`, the cube coordinates
  - `page: u32`
  - `start: u32`, the face range start in the page
  - the six per-direction `(offset, count)` pairs
  - a flags word: active, plus whatever the culling needs
- **`first_instance` is the meta slot on every path.** The per-frame origins buffer goes away.

### One origin formula for every path

- The vertex shader computes the cube's camera-relative origin itself, from `meta[instance_index].pos` and two new per-frame values:
  - `camera_cube = floor(camera / CUBE_SIZE)` as `vec3<i32>`
  - `camera_frac = camera − camera_cube · CUBE_SIZE`, computed in f64 on the CPU and then rounded to f32
- Then: `origin = vec3f((pos − camera_cube) · CUBE_SIZE) − camera_frac`. The integer part is exact.
- **Put the two values in a terrain-only uniform** (group 2), not in `FrameUniforms`, so sky, outline and overlay stay untouched.
- **The CPU path uses the same formula,** as a Rust function with a unit test, for its frustum and direction tests. The CPU and GPU then cull on the same numbers.
- Update the shader header's binding and precision comments. A world coordinate still never reaches f32.
- The goldens must pass **without regeneration**. The origin math changes by at most an ulp, well inside the tolerance. If a golden fails, stop and report rather than regenerate.

### The Hi-Z pyramid (new `render/hiz.rs` plus `shaders/hiz.wgsl`)

- The depth target (`renderer.rs` and the offscreen screenshot path) gains `TEXTURE_BINDING` usage.
- **Pyramid:** an `R32Float` texture with a full mip chain.
  - Mip 0 is the depth target's size, filled by a compute copy.
  - Mip k+1 is a 2×2 **min** reduction of mip k, because in reverse-Z the smaller depth is the farther one and occlusion needs the farthest.
  - At odd sizes, the last row and column of mip k+1 also fold in the extra texel row or column of mip k, so no texel of mip k is ever skipped. Write the rule and a small diagram in the shader header. This is the classic Hi-Z bug; it gets a unit-style test below.
- One dispatch per mip: mip k bound as sampled, mip k+1 as a write-only storage texture.
- Recreated on resize together with the depth target.

### The culling compute pass (new `shaders/cull.wgsl`)

One thread per meta slot; inactive slots exit. Per frame, in order:

1. **Early cull:**
   - For each active slot whose `visible` bit (from last frame) is set and that passes the frustum test, emit its commands to the **early** list.
   - Frustum test: the same plane test as the CPU `Frustum`, on the camera-relative AABB from the formula above.
2. **Early draw:** render pass 1 draws the early list. It loads color and depth after the sky.
3. **Build the Hi-Z pyramid** from the depth target.
4. **Late cull:** for each active slot:
   - `visible = frustum && !occluded`, tested against the new pyramid.
   - If visible and not emitted early, emit to the **late** list.
   - Write the `visible` bit for next frame.
5. **Late draw:** render pass 2 draws the late list, loading color and depth.

**Occlusion test** (conservative, so it may keep an occluded cube but must never drop a visible one):
- Project the 8 AABB corners with `view_proj`. If any corner has `w ≤` the near plane, or the AABB contains the camera, the cube is **visible**.
- Otherwise take the screen rectangle in mip-0 texels and the nearest depth of the box, which is the max z/w in reverse-Z.
- Pick the mip level at which the rectangle spans at most 2×2 texels.
- Read the texels covering it, clamped to the texture. The farthest occluder depth is their min.
- The cube is occluded iff `nearest < farthest`.
- Document every step in the shader, including why each is conservative.

**Emitting commands:**
- One command per non-empty, non-skipped direction, using 2.2's `visible_directions` rule ported to WGSL with the same comparisons.
- Commands go into **per-page regions**. Each frame the CPU writes `region_base[page]`, a prefix sum over pages of the resident cubes' non-empty direction counts. That is a bound the CPU already knows without touching cubes per frame: keep a per-page running total updated on upload and remove.
- The shader appends with `atomicAdd` on a per-page counter.
- Each frame, `clear_buffer` the counters and the command regions before the cull dispatches, so a region's unused tail is zero-count draws.
- Draw: per page, bind its group once, then `multi_draw_indirect(region_base, region_len)`.
- Early and late lists are two separate regions sets: one buffer, two halves.
- **Do not use `multi_draw_indirect_count`.** Metal lacks it, and the zero-tail works everywhere. Note in the README that it is a later optimization for Vulkan and DX12.
- Command order inside a region is nondeterministic (atomics). That is fine: opaque, depth-tested terrain has no order-dependent pixels. The path-equality tests below prove it.
- New and re-meshed cubes start with `visible = 0`. The late pass picks them up the same frame, so a fresh pass renders correctly on its first frame. Occlusion takes effect from the second frame of a view.

### Paths, selection and stats

Three paths, chosen once at construction and logged once:

| Path | When | Culling | Draw |
| --- | --- | --- | --- |
| `gpu-cull` | MDI available (2.2's rule) and `DownlevelFlags::COMPUTE_SHADERS` | Compute: frustum, Hi-Z, directions | `multi_draw_indirect` per page, two phases |
| `cpu-cull` | `JBM_NO_GPU_CULL=1`, or a `TerrainPass` setter | 2.2's CPU frustum and directions, with meta slots and the new origin formula | `multi_draw_indirect` per page |
| `fallback` | no MDI, or `JBM_NO_MDI=1` | as `cpu-cull` | Direct draws |

**GPU stats:**
- The cull shader counts into a small atomic stats buffer: `candidates` (active slots), `frustum_culled`, `occluded`, `drawn_early`, `drawn_late`, `commands` and `faces`.
- The buffer is copied each frame into a ring of 3 `MAP_READ` buffers, read without blocking when a map completes. The overlay shows stats one or two frames late; say so.
- `TerrainPass::read_cull_stats_blocking(gpu) -> CullStats` waits for the current frame, for tests and benches.
- `TerrainStats` keeps its fields. On `gpu-cull`, the CPU-known ones (`meshed`, `pages`, `page_bytes`, `used_faces`) stay exact, and `draw_calls` counts the `multi_draw_indirect` calls.
- **Overlay:** one line with the path name and `drawn / frustum-culled / occluded`. Touch the overlay only for that.

## Tests

**Pure logic (client unit tests):**
- The origin formula against `Camera::relative` (f64) within one f32 ulp of the result, for cameras near 0, near ±10⁶ blocks, and on exact cube borders, including negative.
- `CubeMeta` layout offsets.
- The per-page region bound stays correct across upload, re-mesh and remove: a seeded churn checked against a recount.
- The Hi-Z reduction rule on a CPU model of the shader: random depth images of odd and even sizes (1×1, 3×5, 17×9, 640×361). Every mip texel equals the min over exactly the mip-0 texels it covers. Port the indexing as a Rust function that the test and the WGSL comments both describe.

**GPU tests**, skipped via `gpu_or_skip` with no adapter, as before:
- The `terrain_spawn` and `edit_spawn` goldens pass unchanged on the default path. Do not regenerate.
- **Path equality:** `gpu-cull`, `cpu-cull` and `fallback` render `terrain_spawn` and `edit_spawn` **pixel-identically** (exact). On an adapter without the GPU path, the test says so and checks what exists.
- **No popping:**
  - Render a 60-frame camera path through the spawn region: turning on the spot, moving forward, and dropping under the surface into a carved room and back out.
  - At **every** frame, `gpu-cull` must equal `cpu-cull` pixel for pixel, using the same pass object across frames so the two-phase state is real.
  - This is the test that catches a wrong Hi-Z or a lost visibility bit; it must run with real occlusion, so check that `occluded > 0` on some frames.
- **Cave culling:**
  - Generate the spawn region, then carve a closed 8×5×8 room about 20 blocks under the surface, using the same block edits the game uses.
  - Put the camera in the room looking horizontally and render 3 frames.
  - On the third frame, `occluded` is at least **80%** of the frustum-passing candidates, and the image equals `cpu-cull`.
  - Print the counts.
- **Open view:** from the `terrain_spawn` camera on the surface, `occluded` stays small and the image is unchanged. Print the counts.
- **Slot reuse:** 2.2's churn test (200 cubes, tiny pages, re-upload half, remove a quarter) renders identically on `gpu-cull` and against a freshly built pass. Meta slots and region bounds must pass their invariant checks.
- **Resize:** render, resize the target to an odd size (e.g. 333×217), render again. Equal to `cpu-cull`, with no validation error.

Run the GPU tests 10 times in a row before reporting: two-phase state bugs are often intermittent.
