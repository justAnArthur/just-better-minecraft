# 0.6 Headless server test helpers and criterion bench skeleton

**Goal:** a place and a pattern for headless simulation tests and for benchmarks, so later tasks (tick loop, worldgen, meshing) just add cases.

**Read:** CLAUDE.md, READMEs of crates/server, crates/testkit, crates/core. docs/design.md "Simulation" (context only).

## Scope

- `jbm-server`: a minimal tick clock, no world yet.
  - `pub struct TickClock` with fixed rate `TICKS_PER_SECOND: u32 = 20`, `pub fn new()`, `pub fn tick_count(&self) -> u64`, and `pub fn advance(&mut self, elapsed: std::time::Duration) -> u32` that accumulates time and returns how many whole ticks are due (capped at `MAX_CATCH_UP_TICKS = 10` per call to avoid a spiral of death; the excess time is dropped and counted in `pub fn dropped_ticks(&self) -> u64`). Pure logic: no threads, no sleeping, no real clock reads.
  - Unit tests: 50 ms → 1 tick; 49 ms then 1 ms → 0 then 1; 1 s → 10 ticks with 10 dropped; zero duration → 0.
- `jbm-testkit`: `pub struct HeadlessServer` wrapping a `TickClock` with a manual, deterministic time source: `pub fn new()`, `pub fn step(&mut self, ticks: u32)` (advances exactly that many ticks), `pub fn run_for(&mut self, d: Duration)`, `pub fn tick(&self) -> u64`. Doc comment: this is the harness later stages extend with a world, a fake client channel and replay recording.
  - Integration test `crates/testkit/tests/headless.rs`: steps 100 ticks and asserts the count; `run_for(5s)` in 50 ms increments yields exactly 100 ticks.
- Benches with `criterion` (latest stable; add to `[workspace.dependencies]` and as dev-dependency only):
  - `crates/core/benches/core_bench.rs` with one sample bench (`criterion_group!`), e.g. hashing a 32³ `u16` array, named `sample/fill_32cubed`. Register with `[[bench]] name = "core_bench" harness = false`.
  - `crates/server/benches/tick_bench.rs`: bench `tick_clock/advance_1000` calling `advance` 1000 times with 16 ms steps.
- `cargo bench --workspace -- --test` must run every bench once quickly (criterion test mode); this is what CI will call.
- Update READMEs of core, server, testkit: what exists, how to add a headless test, how to add a bench (file location, `harness = false`, naming `<area>/<case>`).

## Acceptance

- `cargo test --workspace` passes including the new unit and integration tests.
- `cargo bench --workspace -- --test` passes.
- `cargo bench -p jbm-server` produces real criterion numbers (mention the median in the report).
- fmt, clippy -D warnings pass.

## Out of scope

No networking, channels, world or ECS (1.3 does that). No CI file changes (0.2). Do not touch `crates/client`.
