# 1.1 Cube storage, palette compression, block state registry

**Goal:** the world's core data type. A 32³ cube of block states stored as a palette plus bit-packed indices, coordinate types that work across the whole ±2³¹-cube world, and a registry that interns block states to `u32` ids. The mesher (1.4), terrain (1.5), collision (1.6) and LOD (2.4) all build on this, so correctness and speed matter more than features.

**Read:** CLAUDE.md, crates/core/README.md, docs/design.md "World representation".

## Scope (all in `jbm-core`, no new dependencies)

### `coords` module
- `pub const CUBE_SIZE: i32 = 32`, `CUBE_BITS: u32 = 5`, `CUBE_VOLUME: usize = 32768`.
- `CubePos { x, y, z: i32 }`: cube coordinates.
- `BlockPos { x, y, z: i64 }`: world block coordinates. i64 is required because `i32::MIN * 32` overflows i32.
- `LocalPos`: a block inside a cube, 0..32 on each axis. Constructor `LocalPos::new(x, y, z) -> Option<Self>` plus a `debug_assert`-checked `new_unchecked`. Linear index `index() = (y * 32 + z) * 32 + x` (x fastest, then z, then y). Also `from_index(usize)`.
- Conversions: `BlockPos::split(self) -> (CubePos, LocalPos)` and `CubePos::block(self, LocalPos) -> BlockPos`. Use floor division (`>> 5` and `& 31` on i64), so -1 maps to cube -1, local 31.
- Derive `Debug, Clone, Copy, PartialEq, Eq, Hash` on all of them. Add `Ord` on `CubePos`.

### `block` module
- `BlockStateId(pub u32)` with `BlockStateId::AIR = BlockStateId(0)`.
- `BlockRegistry`:
  - `register(def: BlockDef) -> Result<BlockId, RegistryError>`.
  - `BlockDef { name: String /* "namespace:path" */, properties: Vec<Property>, solid: bool, opaque: bool }` and `Property { name: String, values: Vec<String> }`.
  - Every combination of property values gets a consecutive state id. The first value of each property is the default.
  - Air is always registered first, at construction, as `base:air` (state 0, not solid, not opaque).
  - Errors: duplicate block name; malformed name (needs exactly one `:` with non-empty `[a-z0-9_.]` parts on both sides); empty property value list; duplicate property names; too many states in total (more than `u32::MAX`).
  - Lookups:
    - `block(name) -> Option<BlockId>`
    - `default_state(BlockId) -> BlockStateId`
    - `state(name, &[(&str, &str)]) -> Option<BlockStateId>`, where unspecified properties take their defaults
    - `info(BlockStateId) -> &StateInfo`: block id, name, property values, solid, opaque. The `solid` and `opaque` flags are stored per state in a flat `Vec` so hot paths can do an O(1) index.
    - `state_count()`
    - `with_property(BlockStateId, prop, value) -> Option<BlockStateId>`
  - The registry is built once at startup and then shared read-only. No interior mutability.
- `builtin::register(&mut BlockRegistry)` adds the hardcoded Stage 1 blocks, all in the `base:` namespace. Stage 3 moves them into a mod.
  - stone, dirt, grass_block, sand, water (not solid, not opaque), glass (solid, not opaque), oak_planks
  - oak_log with property `axis` = `y|x|z`
  - leaves (solid, not opaque)
  - `builtin::Blocks` returns their default state ids for convenience.

### `cube` module: `Cube` (paletted storage)
- **Layout:**
  - A palette `Vec<BlockStateId>`.
  - Indices bit-packed into `Vec<u64>`. Entries never straddle a word: `entries_per_word = 64 / bits`, so 64 is the word size and padding bits are unused.
  - Bits per entry are `max(1, ceil(log2(palette_len)))`, up to 15.
  - A cube with exactly one palette entry has no index array (an empty Vec). An all-air or all-stone cube costs only its palette.
- **API:**
  - `Cube::filled(BlockStateId)`
  - `Default` is all air
  - `get(LocalPos) -> BlockStateId` and `get_index(usize)`
  - `set(LocalPos, BlockStateId) -> BlockStateId` returns the old state, with `set_index` alongside
  - `fill(BlockStateId)`
  - `uniform() -> Option<BlockStateId>`
  - `palette() -> &[BlockStateId]`
  - `bits_per_entry() -> u32`, which is 0 for uniform
  - `heap_bytes() -> usize`, the bytes owned on the heap, for the 1.8 memory bench
  - `iter() -> impl Iterator<Item = BlockStateId>` in index order, fast and without a per-element bounds check where avoidable
  - `from_fn(impl FnMut(LocalPos) -> BlockStateId)`
  - `compact()`
- **Growth:**
  - Setting a state that is not in the palette appends it.
  - When the palette outgrows the current width, repack all entries at the new width.
  - Setting a block to the state it already has must not touch the palette.
  - Finding a state in the palette must not be a linear scan once the palette is large. Use a linear scan up to 16 entries, then a reverse map (`HashMap<BlockStateId, u16>` with a fast hasher written locally, or a sorted side table). It is your choice, but the bench must show it.
- **`compact()`:**
  - Drops unused palette entries, remaps indices and shrinks to the minimal width, going back to no array when one state remains.
  - It is NOT called automatically by `set`. Callers run it after bulk edits or before saving. Document this.
- **Invariants:**
  - Every index in the array is less than `palette.len()`.
  - Palette entries are unique.
  - Add a `#[cfg(test)] fn check_invariants(&self)` that tests call after every operation.

## Tests (unit, next to the code)

- Coordinate round-trips for positive, negative and extreme values: `i32::MIN`/`MAX` cubes, and block -1 → cube -1 / local 31. `LocalPos` index round-trip over all 32768.
- Registry:
  - air is state 0
  - state ids are consecutive per block
  - `state()` with partial properties
  - `with_property`
  - every error case
  - the builtin blocks register cleanly
  - the `info` flags are right
- Cube:
  - Uniform cube: no array, `heap_bytes` small, `bits_per_entry() == 0`.
  - Growth through 1→2→3→5→17→257→4097 distinct states. Check the width after each step, and check that every previously set block still reads back.
  - `set` returns the old state; setting the same state leaves the palette unchanged.
  - `compact()` after overwriting most states shrinks palette and width, and keeps every value.
  - A randomized test: 50 000 random sets with a small local xorshift (no rand dependency) against a plain `Vec<BlockStateId>` of 32768 reference values, checking invariants every 1000 ops and the full contents at the end.
  - The worst case of 32768 distinct states, which needs 15 bits.

## Benches (`crates/core/benches/core_bench.rs`, keep `sample/fill_32cubed`)

- `cube/get_all_16_states`: read every block of a cube with a 16-state palette.
- `cube/set_all_16_states`: write every block of a cube cycling through 16 states, starting from air.
- `cube/palette_growth_4096`: from air, set 4096 distinct states, one block each.
- `cube/iter_sum_16_states`: `iter()` over a 16-state cube, folding ids.
