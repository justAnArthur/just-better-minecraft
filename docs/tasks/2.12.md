# 2.12 Playground: a debug world and an egui debug panel

**Goal:** a live debug panel with every render debug view, switchable at runtime, plus the client and server stats, and a small deterministic debug world for checking meshing and LOD by eye. This is the tool that 2.13 (meshing and the full-detail radius) and 2.14 (height-exact LOD) are tuned with, so it measures what they will change: faces, triangles, draws, and cubes per level.

**Read:**
- CLAUDE.md, the client, server and game READMEs.
- docs/tasks/2.10.md (level tint) and 2.11.md (the restructuring: `RenderSettings`, `HudSnapshot`, `TerrainSync`, `testing::OffscreenRig`).
- `crates/client/src/app.rs` (the event loop, keys around line 770, the overlay around line 550), `hud.rs`, `render/settings.rs`, `render/overlay.rs`, `render/terrain/*` (`TerrainStats`, the cpu/gpu cull paths and the fallback path), `render/shaders/terrain.wgsl`.
- `crates/server/src/run.rs` (`spawn`, `drive`, `ServerHandle`), `server/stats.rs` (`ServerStats`), `server/config.rs`, `worldgen/mod.rs` (`Preset`) and `crates/server/assets/worldgen/*.json`.
- `crates/game/src/main.rs`.

## Dependency exception

Add `egui`, `egui-winit` and `egui-wgpu` **0.37** (the `[workspace.dependencies]` entries, used by `jbm-client` only). egui-wgpu 0.37 needs wgpu 30 and winit 0.30, which match the workspace. This overrides the 1.2 rule against wgpu-version-coupled crates. The cost: a future wgpu upgrade must wait for a matching egui release. Use default features unless one pulls in something heavy (say which in the report). No other new crates.

## Scope

Commit in this order. Each step builds and passes the gates on its own.

### A. egui integration (client)

- An `egui` pass drawn last, over sky, terrain, the crosshair and the hotbar, into the same surface view. Keep it in one module (`crates/client/src/debug_ui/` or `render/egui_pass.rs`; your choice, explain it).
- **F3** toggles the panel. When it is open, the cursor is released and egui gets mouse and keyboard input; game keys are not applied while egui wants the keyboard (`wants_keyboard_input`), and clicks do not break or place blocks. When it is closed, input works exactly as it does now. Escape still releases the cursor first.
- The existing bitmap overlay (`OverlayText`, the HUD lines) stays as the default when the panel is closed, so goldens and tests that read it keep working. When the panel is open, its Stats section shows the same `hud::lines` content instead.
- Offscreen tests do not create egui (no window). `OffscreenRig` and the goldens are untouched.

### B. The panel

One `egui::Window` ("Debug") with collapsible sections:

1. **Stats** (read-only, refreshed every frame):
   - FPS and frame time: average, p99 and worst over the last 120 frames (from `FrameStats`).
   - `TerrainStats`: meshed, drawn cubes, faces, **triangles (= faces × 2)**, indirect commands, draw calls, pages, page bytes, used faces.
   - **Per LOD level:** cubes resident, cubes drawn, faces drawn. Add per-level counters to `TerrainStats` (or a sibling struct) on all three draw paths. On the GPU-cull path, drawn counts come from the cull readback if one exists; otherwise show "n/a (gpu cull)" rather than a wrong number.
   - Client streaming: `TerrainSync::in_flight()`, `in_flight_lod()`, the queue lengths.
   - **Server:** the `ServerStats` snapshot (tick, world cubes, gen in flight, LOD stats, spans, saves, per-player pending). See C.
   - Camera: position, cube, yaw and pitch, and the current draw path (MDI / fallback, CPU / GPU cull).
2. **Views** (checkboxes; each one also has an env var so tests and screenshots can force it):
   - **Wireframe** (`JBM_WIREFRAME=1`): quad edges over the shaded terrain. Implement it in the terrain fragment shader from the quad-local coordinate (vertex pulling knows the corner, `vertex_index % 6`), so it works on every backend and every draw path without `POLYGON_MODE_LINE`. A second option, "wireframe only", draws the edges on a flat background color.
   - **Chunk borders** (`JBM_CHUNK_BORDERS=1`): line boxes around every resident cube in a radius around the camera (default 3 cubes for LOD0; coarse levels draw their own cube size), colored by level with the 2.10 tint palette. A small line pipeline (`LineList`, CPU-built vertex buffer, depth-tested) in its own module.
   - **Exploded cubes** (`JBM_EXPLODE=<gap>`): each cube's geometry is shifted away from the camera's cube by `gap × (cube index offset)` blocks (slider 0..8), so cube seams and per-cube meshes are visible. Do it in the vertex shader through a uniform; culling keeps working (widen the cull bounds by the explode offset, or skip frustum cull while exploded; say which).
   - **Level tint** (F4, `JBM_LOD_TINT=1`): the existing toggle, mirrored here.
   - **Per-level toggles:** one checkbox per LOD level 0..=6 (`JBM_LEVELS=0,1,3` style mask). A hidden level is not drawn. Coverage does not change: a hidden level leaves a hole where it would draw, which is the point.
   - **Freeze culling** (`JBM_FREEZE_CULL=1`): culling keeps the camera frustum and position from the moment it was frozen while the real camera moves, so you can fly out and look at what was culled. Draw the frozen frustum as lines (reuse the line pipeline). On all draw paths, including GPU cull.
   - **Fog** on/off, **force CPU cull**, **force fallback (no MDI)**: if a path can be switched live cheaply, do it; if the path is fixed at startup, show it read-only and say why.
3. **World:**
   - **View radius:** sliders for the LOD0 radius (`view_radius`, in cubes) and the ring radius (`lod_view_radius`), applied live on the server (see C). The client's fog, fade and ring radii follow (`RenderSettings::far_radii`, `ServerConfig::ring_radii`, one rule).
   - A read-only line with the world preset, seed and the server's config numbers.

Keep all debug state in `RenderSettings` (extend it; `from_env()` reads the new env vars), and keep the panel code free of rendering logic: the panel edits settings, the renderer reads them.

### C. Server stats and live radius (server, game)

`jbm-client` does not depend on `jbm-server`, and the link carries only protocol messages. Do not add stats to the protocol. Instead:
- `run::spawn` keeps a shared snapshot: the server thread writes `server.stats()` into an `Arc<Mutex<Option<ServerStats>>>` every 10 ticks (0.5 s). `ServerHandle::stats() -> Option<ServerStats>` clones it.
- `ServerHandle::set_view_radius(view_radius, lod_view_radius)` sends a command over a control channel that the server thread applies at the start of the next tick. On the server: change the config, recompute desired sets and ring windows (the same code paths a player crossing a cube border uses), and let the existing unload rules drop what fell outside. Clamp to sane bounds (LOD0 2..=32 cubes, rings 2..=16). If this needs more than ~200 lines in the server, stop after the stats part, make the slider client-only (a draw-distance cap that hides cubes beyond the radius), and explain in the report.
- `jbm-game` connects them: `ViewSetup` gets an optional `debug: Option<DebugHooks>`, defined in `jbm-client` as plain closures: `server_lines: Box<dyn Fn() -> Vec<(String, String)> + Send>` (label and value rows, formatted in the game crate from `ServerStats`) and `set_view_radius: Box<dyn Fn(u32, u32) + Send>`. The client stays free of server types.
- `ServerHandle` must still be joined on exit, and `stop()` keeps returning the `Server`.

### D. Debug world (server, game)

- A third `Preset::Playground`, selected with `JBM_WORLD=playground` (game reads it; `overworld` and `classic` also accepted; unknown values are a one-line error, not a panic). It is a fixed layout around spawn, not noise:
  - a flat stone plane at y = 64 with a grass top,
  - a staircase of 1-block steps up to y = 96,
  - a vertical cliff wall 64 blocks tall,
  - a 1-block-wide pillar 128 blocks tall,
  - a pit 32 blocks deep and 8 wide,
  - a water pool at sea level next to sand,
  - a checkerboard of two block types (worst case for greedy meshing),
  - a 45° ridge (diagonal stairs) and a dome, so LOD shape errors are visible.
  
  Each feature is at a fixed offset from spawn with clear ground between them, and the plane extends far enough (at least the outermost ring) that LOD levels can be compared on each feature.
- Implement it as a worldgen JSON graph if the graph language can express it cleanly. Otherwise, use a small Rust generator behind the same `Preset` interface, but then the LOD sampling path (`sample_lod`, the surface/LOD column rule) must work on it too. Say which you chose and why.
- Spawn on the plane, facing the features. Saves: a playground world never saves (no `world_dir`), whatever `JBM_NO_SAVE` says.
- Generation must be deterministic: same seed, same cubes.

## Tests

- **Settings:** each env var parses into `RenderSettings` (unit tests, as in 2.11c).
- **Render tests**, on the offscreen rig with `Classic` or `Playground`:
  - wireframe on draws edge-colored pixels on quad edges and leaves interiors shaded;
  - chunk borders draw level-colored line pixels;
  - exploded (gap 4) shifts a known cube's pixels away from the center;
  - hiding level 0 removes LOD0 pixels (tint on, so you can assert the color);
  - freeze culling: freeze, rotate the camera 180°, and the frozen frustum's cubes are still what gets drawn (the drawn count matches the frozen count, not the new view's).
  
  Run each on the default path, `JBM_NO_MDI=1` and `JBM_GPU_CULL=1`, wherever the view applies.
- **Per-level stats:** the per-level drawn counts sum to the total drawn, on every path that has them.
- **Server:** `ServerHandle::stats()` is `Some` within 1 s of spawn and its tick advances; `set_view_radius` from 4 to 8 grows the desired LOD0 set and from 8 to 4 shrinks the server's resident cubes after settling (a test in `crates/server/tests/`).
- **Playground:** generation is deterministic (two runs, same hashes); each feature exists at its offset (assert block states); `sample_lod` of the playground agrees with downsampling the full cubes on the same rule as the other presets' LOD tests.
- **egui:** a unit test that the input routing works: when the panel wants the keyboard, `map_key` input does not reach `Input`; when it is closed, it does. Use whatever seam keeps it testable without a window; no egui render test.
- Goldens unchanged (debug views default off). The existing tests pass.
