# 1.8 Benchmark 16³ vs 32³ cubes

**Goal:** measure what cube size costs before Stage 2 builds LOD, persistence and GPU suballocation on top of it. Add a `cube16` compile-time feature that switches `CUBE_BITS` from 5 to 4. Then add a bench and a metrics example that run the same terrain region at both sizes and report:
- meshing time
- single-edit re-mesh time
- memory
- draw calls

The orchestrator records the decision in docs/progress.md from your numbers. You do not decide.

**Read:**
- CLAUDE.md, and the READMEs of crates/core, crates/client and crates/game.
- docs/design.md "World representation".
- `crates/core/src/coords.rs`, `cube.rs`, `crates/client/src/mesh/` (greedy.rs, face.rs), `crates/client/src/world.rs`.
- `crates/server/src/terrain.rs`: only `Generator::new` and `surface_height`.

**Parallel work:** task 1.6 is changing `protocol.rs`, `crates/client/src/app.rs`, `input.rs`, `world.rs` (it adds a `BlockShapes` impl) and the server. To keep merges simple:
- Do not touch `app.rs`, `input.rs`, `protocol.rs` or `crates/server/src/server.rs`.
- In `world.rs`, change only the `cube_center` literal.

## Scope

### `cube16` feature (`jbm-core`, `jbm-client`)

- `jbm-core` gets feature `cube16`:
  - `CUBE_BITS = 4` under it, else 5.
  - `CUBE_SIZE` and `CUBE_VOLUME` derive from `CUBE_BITS`.
  - All masks and shifts in coords.rs derive from them too (`& 31` becomes `& (CUBE_SIZE - 1)` or a `CUBE_MASK` const).
- **Client mesher** (greedy.rs, face.rs, world.rs) and any other lib code that writes `32`, `31`, `33`, `34`, `<< 5`, `& 31` and so on as a cube dimension: derive from the core constants.
  - **Face packing:** the 8-byte layout keeps its 5-bit fields. 16 fits, and the shader stays unchanged. Only the debug asserts and loops use `CUBE_SIZE`.
  - Check the WGSL and `render/chunks.rs` for any hardcoded cube size, and fix it the same way.
- `jbm-game` gets a passthrough feature, `cube16 = ["jbm-core/cube16"]`.
- **Tests:**
  - Size-agnostic tests stay as they are, using the constants where they used literals.
  - Tests whose expectations only make sense at 32³ (hand-computed face lists, goldens, streaming shapes) get `#[cfg(not(feature = "cube16"))]` with a one-line reason.
  - Mark as few as possible; most mesher tests should run at both sizes.
- **Default build:**
  - No behavior change at 32³.
  - Every existing test and golden passes unchanged, with no golden regenerated.
  - Mesh and core bench numbers stay within noise.
- Do not change server code. The server compiles under `cube16` but is not required to behave correctly there. Document that in the core README next to the feature.

### Bench (`crates/game/benches/cube_size.rs`, registered in `crates/game/Cargo.toml`)

**Region:** world blocks x, z ∈ [0, 128) and y ∈ [32, 128). That is 48 cubes at 32³ and 384 at 16³.

**Content** is built in the bench with `Cube::from_fn`, from `Generator::new(DEFAULT_SEED, blocks).surface_height(x, z)` and the 1.5 layering:
- grass at h
- dirt from h-3 to h-1
- stone below
- sand where h ≤ 61
- air above

Building it locally keeps the server's own `generate` out of the `cube16` question. Cubes outside the region but adjacent to it are built the same way, so border faces are realistic.

**Benches**, criterion, same names at both sizes (the feature selects the size):
- `cube_size/mesh_region`: build `MeshInput`s (center + 26 neighbors) for every region cube outside the timed loop, then time meshing all of them serially with `greedy::mesh`.
- `cube_size/remesh_edit`: time meshing the single cube that contains block (64, h(64,64), 64), the latency floor for a block edit. If 1.7 neighbor dirtying matters, note it in the report: an edit on a cube border re-meshes up to 8 cubes.
- `cube_size/build_region`: time building all the region's cubes with `Cube::from_fn`, as a proxy for generation cost per volume.

### Metrics example (`crates/game/examples/cube_size_metrics.rs`)

Run with `cargo run -p jbm-game --release --example cube_size_metrics [--features cube16]`. It prints one aligned table for the region:
- cube size, cube count, uniform cubes (air or stone), non-empty meshes (= draw calls with today's renderer)
- total faces, mesh bytes (faces × 8), bytes per non-empty mesh (mean and max)
- cube storage: sum of `heap_bytes()` + `size_of::<Cube>()` per cube, plus a documented per-entry `HashMap` overhead estimate
- **Streaming granularity:** the number of `CubeData` messages needed to cover a 256-block-radius, ±128-block-high view cylinder at that size. That is R and V in cubes chosen to cover the same volume. Count with the same `dx² + dz² ≤ R²`, `|dy| ≤ V` rule as `crates/server/src/streaming.rs`, but compute it locally; do not call into the server.
- **GPU** (when `gpu_or_skip()` finds an adapter):
  - Upload every region mesh to a `TerrainPass`, then render one 1280×720 offscreen frame from above the region looking down 45°.
  - Report the mean wall time of 50 frames, each followed by a device poll wait.
  - Print "GPU: none" otherwise.

## Report

Include both tables (32³ and 16³) and the three bench medians at both sizes, run with `--release` benches on the same machine back to back.

Also state, in one line each, any 16³ issue you hit: precision, packing, assumptions in the mesher. If the machine is busy, say so; the orchestrator may re-run on an idle machine.

## Acceptance

- fmt, clippy `-D warnings`, `cargo test --workspace` and `cargo bench --workspace -- --test` pass in the default build.
- `cargo clippy -p jbm-core -p jbm-client --all-targets --features jbm-core/cube16 -- -D warnings` passes.
- `cargo test -p jbm-core -p jbm-client --lib --features jbm-core/cube16` passes.
- `cargo bench -p jbm-game --bench cube_size -- --test` passes with and without `--features cube16`.
- The example runs at both sizes.
- The README of crates/core documents the feature and its limits (server unsupported, CI does not run it). The README of crates/game documents the bench and the example.

## Out of scope

- Changing the default cube size. That decision is the orchestrator's.
- Multi-draw indirect and suballocation (2.2), and any renderer change beyond removing size literals.
- `app.rs`, `input.rs`, `protocol.rs`, the server crate, and CI.
- Making the server or the end-to-end game tests work under `cube16`.
