# 2.2 GPU buffer suballocator, multi-draw indirect, fallback path

**Goal:** stop paying one buffer, one bind group and one draw call per cube.
- All cube meshes live in a few large face buffers, the "pages", managed by a CPU-side suballocator. A re-mesh replaces a slot; it never creates a buffer.
- The terrain is drawn with one `multi_draw_indirect` per page, using one indirect command per visible cube and face direction.
- Back-facing directions are skipped per cube, as docs/design.md "Rendering" specifies.
- Hardware without the needed support gets a plain loop of direct draws over the same buffers, with the same image.

Frustum culling stays on the CPU; GPU culling is 2.5.

## Scope

### Suballocator (`jbm-client`, new `render/suballoc.rs`, pure logic, no wgpu)

- `Suballocator::new(capacity: u32)` manages one page of `capacity` units; a unit is one 8-byte face.
  - `alloc(len) -> Option<Range<u32>>` is first-fit over an ordered free list.
  - `free(range)` coalesces with both neighbors.
  - `used()`, `largest_free()` and `free_ranges()` are for tests and stats.
- **Invariants**, checked by a `check_invariants()` used in tests:
  - Free ranges are sorted, disjoint, non-adjacent (always coalesced) and in bounds.
  - Used plus free equals capacity.
  - Double free or freeing an unallocated range is a debug assert. It is a caller bug.
- `alloc(0)` is never called; empty meshes allocate nothing.

### Paged face storage (`render/chunks.rs`)

- **Pages:** a face page is one `STORAGE | COPY_DST` buffer of `page_faces` faces, plus its own suballocator and bind group.
  - The default size is 4M faces (32 MiB). Clamp it to `max_storage_buffer_binding_size` and `max_buffer_size` from the device limits.
  - A test-only constructor takes a tiny page size.
  - When no page fits a mesh, create a new page.
  - A mesh larger than a whole page is impossible: the max faces per cube is bounded by `6 · CUBE_SIZE³ / 2`. Assert the bound at construction, and size pages to hold at least one worst-case cube.
- **Upload:** `upload(pos, &MeshOutput)` frees the cube's old range, if any, then allocates and `write_buffer`s the faces. Keep the cube's six per-direction sub-ranges from `MeshOutput::ranges`.
  - **Freed ranges can be reused immediately.** wgpu orders `queue.write_buffer` before the next submit's commands, and earlier frames were already submitted. Put that argument, with the wgpu doc reference, in a comment.
  - Empty meshes keep an entry with no allocation, as today.
- `remove(pos)` frees the range.
- **Pages are never freed or compacted in this task.** Note it as a known limit: fragmentation grows until 2.6 or a later compaction task.

### Drawing

- **Shader:**
  - Faces now come from a page buffer.
  - `faces[vertex / 6]` stays correct if the draw's `first_vertex` is `(range.start + dir_range.start) · 6`. The vertex index includes `first_vertex`; verify this against the WGSL and wgpu docs and note it in the shader header.
  - The origin slot keeps coming from `instance_index` via `first_instance`.
  - Update the shader's header comment to the new binding scheme.
- **Per visible cube** (CPU frustum test as today), in sorted `CubePos` order as today: emit one command per face direction with a non-empty range, **skipping back-facing directions**.
  - Use the camera-relative AABB.
  - Skip `+X` when `rel_min.x ≥ 0`, because every +X face plane is then at or beyond the camera's x and faces away. Skip `-X` when `rel_max.x ≤ 0`, and likewise for Y and Z.
  - Write the one-line proof per axis in a comment.
  - This must not change the image, since back-face culling already discards those faces.
- **MDI path:** used when the adapter has `DownlevelFlags::INDIRECT_EXECUTION` and the device was created with `Features::INDIRECT_FIRST_INSTANCE`.
  - `gpu.rs` requests `INDIRECT_FIRST_INSTANCE` only if the adapter supports it; never fail device creation over it.
  - Per frame, write `DrawIndirectArgs` into one indirect buffer (`INDIRECT | COPY_DST`, grown like the origins buffer), grouped by page.
  - Draw: bind each page's group once, then one `multi_draw_indirect` over that page's commands.
- **Fallback path:** the same commands and buffers, issued as `pass.draw(first_vertex..first_vertex + count, slot..slot + 1)` in a loop. Direct draws accept `first_instance` without the feature.
  - Selected automatically when MDI is unavailable.
  - Forcible with `JBM_NO_MDI=1` or a `TerrainPass` setter, for tests and benches.
  - Log the chosen path once at startup.
- **Stats:** `TerrainStats` gains:
  - `commands`: indirect commands, or fallback draws
  - `draw_calls`: render-pass draw API calls, so 1 per non-empty page with MDI
  - `pages`
  - `page_bytes`
  - `used_faces`

  Keep `drawn` and `faces`; `faces` now counts only the non-skipped directions. The overlay shows the path (MDI or fallback), draw calls, commands and pages. Touch the overlay only for that line.

## Tests

**Suballocator unit tests:**
- Alloc and free patterns: fill exactly, free the middle, coalesce left, right and both sides, first-fit choice, and failure when only fragmented space remains.
- A seeded random churn of 10,000 operations against a simple bitmap model, with `check_invariants` after every operation.

**Direction culling:** a pure-logic function `visible_directions(rel_min, rel_max) -> [bool; 6]`, unit-tested for a cube in front, behind, straddling each axis, and containing the camera (all six directions visible).

**GPU tests**, skipped via `gpu_or_skip` with no adapter, as the existing ones are:
- The existing `terrain_spawn` and `edit_spawn` goldens pass unchanged on the default path. Do not regenerate them.
- **Path equality:** render the `terrain_spawn` scene through the MDI path and through the fallback path and assert the two images are **pixel-identical** (exact, not the golden tolerance). Do the same for `edit_spawn`. If the adapter lacks MDI, the test says so and checks fallback against the golden only.
- **Slot reuse:** upload 200 cubes into a tiny-page `TerrainPass` that forces at least 3 pages, re-upload half of them with different meshes, and remove a quarter. Then render and compare against a freshly built pass holding only the final meshes. The images must be pixel-identical, and the suballocators must pass `check_invariants`.
- **Stats:** for the `terrain_spawn` scene, `draw_calls ≤ pages` on MDI, `commands ≥ drawn`, and `commands ≤ 6 · drawn`. Assert that directions really are skipped: `faces` is below the total faces of the drawn cubes.
