# 2.14 Height-exact LOD: coarse tops at the true block height

**Goal:** a LOD ≥ 1 column's top face sits at the true height of the terrain it covers, to the block, instead of rounding up to a 2ⁿ-block cell boundary and compounding the 2-of-8 lean level after level. Today the coarse top averages +0.6 / +1.7 / +4.0 / +9.7 / +19.8 blocks above the true surface at L1–L5 (`crates/server/tests/overworld.rs` `lod_surface_accuracy_per_level`), so far hills swell, ring borders show steps, and the user "sees the LOD". After this task the coarse top of every column is the **highest filled block in its footprint**. This is exact (the error is 0) for real data, and within a block for worldgen-sampled data. The coarse surface therefore never sits below the fine one, so skirts keep hiding seams.

## Design (decided — implement this)

### 1. Occupancy rule: any filled child fills the cell

`downsample_cell` changes from "at least 2 of 8 children filled" to "**at least 1 of 8**". The material rule ("what you see from above") is unchanged. Consequences:
- The coarse volume is the union of the fine volume rounded out to cells.
- Thin walls and trunks survive trivially.
- A single floating block now survives as one coarse cell whose height comes from §2. It is no longer dropped.

Update the design.md paragraph and the core docs. The rule stays a pure function of the eight children, so edit propagation stays exact.

### 2. Per-column top height

Every filled cell has a **fill height** `h ∈ 1..=2ⁿ`: the number of blocks from the cell's bottom to the top of its highest filled block.
- **Level 1:** from blocks, `h = 2` if any upper child (dy = 1) is filled, else `1`.
- **Level n:** `h = max over filled children of (dy · 2ⁿ⁻¹ + h_child)`.

**Storage.** Each LOD cube stores `h` only for the **topmost filled cell of each column** of the cube: `tops: [u8; CUBE_SIZE²]`, indexed `x + CUBE_SIZE · z`, with 0 for a column with no filled cell in this cube. Make it a small core type (for example `LodTops`) with an all-full / all-empty fast path so uniform cubes stay cheap. Every other filled cell counts as full (`h = 2ⁿ`), including `h_child` for child cells that are not their child cube's column top.

That approximation flattens overhang undersides. It is local, deterministic, and has no visible cost on the shipped terrain; document it.

**Locality.** A parent's tops are a pure function of its eight child cubes' cells and tops. Make this a core function next to `downsample_octant` / `downsample_region` / `copy_octant`, so:
- the incremental edit path, `rebuild()`, the gen-worker octant (`lod1_octant`) and `fill_octants` all compute tops the same way;
- incremental == rebuild still holds, with tops included.

### 3. Worldgen sampling (`sample_lod`)

Phase 1 already computes each sampled column's true surface (`lod_sample.rs`), then phase 3 throws it away.
- Phase 3 (`reduce_to_cube`) now also produces tops. Derive each child cell's `h` from the sampled column's true surface, clamped to `1..=2ⁿ⁻¹` for the child cell holding the surface, and full below it. Then reduce with the §2 rule.
- **Level 1 stays exact:** `sample_lod` at level 1 equals the downsample of the eight generated LOD0 cubes, **tops included**. Extend `sample_lod_level_1_is_the_downsample_of_generated_cubes` and the playground equivalent to compare tops.
- At levels ≥ 2 the sample grid can miss a peak between samples. The acceptance metric below allows for that.
- Water fills to the sea surface (y = 64 top, a multiple of every cell size up to L6), so ocean tops are full cells and the sea stays flat across ring borders. Keep `ocean_columns_fill_with_water_to_sea_level_at_every_level` passing.

### 4. Wire and disk

- `ServerMsg::LodCubeData` gains the tops; `PROTOCOL_VERSION` becomes 7.
- Storage: `LOD_RECORD_SCHEMA` becomes 3, storing the tops (zstd as now).
- Add `jbm_core::lod::RULE_VERSION` (start at 2) and mix it into `lod_fingerprint`, so saved worlds resample instead of loading lean-high records. Add a test: a store written under a different rule version resamples.
- Fix the stale "kinds 1..=4" docs in `storage.rs`.

### 5. Client: world and mesh input

- `ClientWorld` keeps tops with each LOD cube.
- At level ≥ 1, `MeshInput` carries the cube's tops and those of the same-level neighbours it pads from. The four side neighbours matter, because a side face at the cube border needs the neighbour's fill height.
- Level 0 carries none, and its mesh output must be **bit-identical** to today. The `terrain_spawn`, `edit_spawn` and `mesh_*` goldens, plus the LOD0 bitmask==oracle cases, must stay unchanged.

### 6. Mesher at level ≥ 1

Every cell has a fill height `H`:
- `2ⁿ` for a filled non-top cell;
- its tops value for a column-top cell;
- `0` for air;
- `2ⁿ` for `MISSING_CELL`, which still culls as today.

Faces:
- **+Y face** of a column-top cell sits at `H`, not at the cell top.
- **Side face** from cell A toward neighbour B at the same y covers the vertical interval `[H_B', H_A]`, where `H_B' = H_B` when B culls A's face under today's rules (opaque, missing, equal non-opaque) and `0` otherwise. It is emitted when `H_A > H_B'`. This is what keeps a step between two partial tops closed.
- **Skirts:** same placement rules, but the upper edge is at the cell's `H`.
- **Lids:** keep their semantics.
- **−Y faces:** unchanged.

Greedy merging:
- The merge key includes the face's bottom and top insets (below), so faces with different insets never merge.
- A vertically merged side quad may span several cells only when the result is exactly representable: full cells in the middle, the inset only on the outer edges.
- The bitmask sweep and `mesh/oracle.rs` change in lockstep. Bitmask == oracle on the existing corpus plus ≥ 2,000 seeded random cases with random tops at every level ≥ 1.

### 7. Face format and shader

`PackedFace` gets two 6-bit insets, both in **blocks**, so up to 63 blocks, enough for L6:
- `inset_bottom` raises the quad's lower edge;
- `inset_top` lowers its upper edge, or lowers the plane for a +Y face.

Pack them into the spare bits: word0 28..32 plus word1 24..32. Word1 24..32 is the light nibble, always 15 and never read on the GPU; repurpose it, and update the face docs and tests that assert it. Then:
- `terrain.wgsl` applies the insets in the vertex position (corner y in blocks, after the level scale);
- `quad_corners` mirrors it on the CPU;
- the octant-mask test in the shader still keys off the owner cell, which an inset never leaves.

Level 0 faces always have zero insets.

  - the `h` recurrence;
  - the tops of `downsample_octant` / `downsample_region` against a brute-force reference computed from LOD0 blocks, up to level 3, on random columns;
  - thin walls still survive;
  - `a_single_floating_block_vanishes_at_lod1` is replaced by a test that it survives as one cell of height 1 or 2.

  - incremental == rebuild, tops included: the existing property tests over 2,000 edits × 10 seeds, plus the storage-backed one;
  - sample_lod level-1 exactness, tops included;
  - stored-LOD reload unchanged;
  - the fingerprint/rule-version resample.
- **Accuracy** (restate `lod_surface_accuracy_per_level`): over the same 512 land columns, per level 1..=5, compute the coarse top from cells + tops minus the **max true surface over the column's footprint**.
  - Real-data (ingested) cubes: exactly 0.
  - Worldgen-sampled cubes: `|err| ≤ 1` for ≥ 95 % of columns, and a mean in [−1, 1].
  - Print the coarse top minus the footprint *mean* true height too, for the record.
  - Replace the old `mean ≥ 0` / `p99 ≤ 2·2ⁿ` asserts.
- **Client:**
  - bitmask == oracle as above;
  - a partial top renders at its height: an offscreen test with an L1/L2 column of known `h`, where the top-face pixel row matches the projection of the exact height;
  - a step between two partial tops leaves no hole (sentinel ground color);
  - pack/unpack round-trips the insets, and `quad_corners` matches the shader.
- **Hole tests:**
  - the rings scene (`crates/client/tests/lod_rings.rs`; make `sampled_cube` produce tops from the height grid) and `lod_fly` pass with tolerances **not** grown;
