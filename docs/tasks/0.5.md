# 0.5 Offscreen screenshot test harness

**Goal:** agents can see what the renderer draws. A test renders offscreen with wgpu, saves a PNG, and compares it with a committed golden image. Every later renderer task adds screenshot tests on top of this.

**Read:** CLAUDE.md, crates/client/README.md, docs/design.md "Rendering" (context only).

## Scope (crate `jbm-client`, plus workspace deps)

- Add workspace deps (latest stable versions via `cargo add`, then move them to `[workspace.dependencies]`): `wgpu`, `pollster`, `image` (default-features = false, features = ["png"]), `bytemuck` (features = ["derive"]) if needed. Use `wgpu` default features; do not pin a backend.
- `jbm_client::gpu` module:
  - `pub struct Gpu { pub instance, pub adapter, pub device, pub queue }` with `pub fn headless() -> Result<Gpu, GpuError>`: creates an instance with all backends, requests a high-performance adapter with `compatible_surface: None`, `force_fallback_adapter: false`; returns `GpuError::NoAdapter` if none. Uses `pollster::block_on`. No panics.
- `jbm_client::render::offscreen` module:
  - `pub struct OffscreenTarget` owning an `Rgba8UnormSrgb` texture of given width/height with `RENDER_ATTACHMENT | COPY_SRC`, and `pub fn read_rgba(&self, gpu: &Gpu) -> image::RgbaImage` that copies to a buffer (respecting `COPY_BYTES_PER_ROW_ALIGNMENT` padding), maps it, strips padding and returns the image.
- `jbm_client::render::triangle`: a minimal pipeline (WGSL inline via `include_str!` from `crates/client/src/render/shaders/triangle.wgsl`) that draws one triangle with per-vertex red/green/blue on a fixed dark-gray clear color (0.1, 0.1, 0.1). No vertex buffer: positions and colors come from `vertex_index`. Function `pub fn draw_triangle(gpu: &Gpu, target: &OffscreenTarget)`.
- Screenshot comparison in `jbm_client::testing::screenshot` (behind `#[cfg(any(test, feature = "testing"))]`; add a `testing` cargo feature):
  - `pub fn assert_matches_golden(name: &str, actual: &RgbaImage)`; golden path `crates/client/tests/golden/<name>.png`.
  - If env `JBM_UPDATE_GOLDEN=1`: write/overwrite the golden and pass.
  - If golden is missing: write `<name>.actual.png` next to where the golden would be and panic with a message telling the user to run with `JBM_UPDATE_GOLDEN=1`.
  - Comparison: sizes must match; a pixel differs if any channel differs by more than 3; the test fails if more than 0.5% of pixels differ. On failure write `target/screenshots/<name>.actual.png` and `target/screenshots/<name>.diff.png` (differing pixels magenta, others dimmed grayscale) and panic with counts and both paths. (Thresholds are constants with doc comments explaining they absorb rasterizer differences between Metal, Vulkan and lavapipe.)
  - Helper `pub fn gpu_or_skip() -> Option<Gpu>`: returns `None` and prints "skipping: no GPU adapter" when no adapter exists, but panics instead if env `JBM_REQUIRE_GPU=1`.
- Integration test `crates/client/tests/screenshot.rs` (uses the `testing` feature through a dev-dependency on itself or `required-features`): renders the triangle at 256×256 and calls `assert_matches_golden("triangle", ...)`.
- Generate the golden `crates/client/tests/golden/triangle.png` on this machine with `JBM_UPDATE_GOLDEN=1` and commit it. Verify by running the test again without the env var.
- Unit tests for the comparison function using synthetic images (identical → pass; one pixel off by 10 in 256×256 → pass; 1% of pixels off → fail with `#[should_panic]`; size mismatch → fail).
- Update crates/client/README.md: the screenshot workflow (how to add a test, update goldens, where failure images go).

## Acceptance

- `cargo test -p jbm-client` passes with the golden committed; with `JBM_UPDATE_GOLDEN` unset it compares, not regenerates.
- Changing the clear color in the shader/test temporarily makes the test fail and writes the diff PNG (verify manually, then revert; mention in report).
- fmt, clippy -D warnings, workspace tests pass.

## Out of scope

No window/winit, no camera, no CI file changes (0.2 owns `.github/`). Do not touch `crates/server`, `crates/testkit`.
