# 2.3 Persistence: redb cube storage, zstd, background saving

**Goal:** edits survive restarts and crashes.
- A world is a directory holding one `redb` database.
- Edited cubes are written in batches by a background saver thread, every few seconds and on shutdown. Each batch is one transaction, so a crash never leaves a half-written cube or a half-written batch.
- Cube values are the palette and index array, compressed with zstd.
- When a cube is needed, it is loaded from disk if stored, otherwise generated.
- Once a cube's edits are committed it is no longer pinned, so it is evicted like any other cube. This ends the "pinned cubes grow without bound" issue from 1.7.

## Scope

**New dependencies:** `redb` (latest 3.x, or 2.x if 3.x does not build on 1.98.1), `zstd` (0.13.x) and `tempfile` (dev only). Pin exact versions in `[workspace.dependencies]`. Nothing else.

### Cube codec (`jbm-core`, `cube.rs`, append-only)

- `Cube::encode_with(&self, map: impl FnMut(BlockStateId) -> u32, out: &mut Vec<u8>)`.
- `Cube::decode_with(bytes: &[u8], map: impl FnMut(u32) -> Option<BlockStateId>) -> Result<Cube, CubeDecodeError>`.
- `map` translates between runtime state ids and the world's on-disk ids.
- **Format** (little-endian, documented in the core README):
  - codec version `u8 = 1`
  - `CUBE_BITS` as `u8`, so a 16³ cube is never decoded as 32³
  - palette length `u16`, then palette entries as `u32`
  - bits per entry `u8`
  - packed words as `u64`
- **Decode validates everything:**
  - version and cube bits
  - palette length in `1..=CUBE_VOLUME`, entries unique and mappable
  - bits consistent with the palette length
  - exact byte length
  - every index below the palette length

  The result satisfies `check_invariants`. **Decode never panics** on any input. Rebuilding through `from_fn` is acceptable if it is simpler; report the decode time.
- **Round trip:** `decode(encode(c)) == c` for uniform, two-state, full-palette (4,096+ states, max bits) and random cubes.

### Storage (`jbm-server`, new `storage.rs` or `storage/`)

- `Storage::open(dir, &BlockRegistry, seed) -> Result<Storage, StorageError>` creates the directory and `world.redb` if missing. It is `Send + Sync`, shared as `Arc<Storage>`. A second open of the same directory fails with a typed `Locked` error; never corrupt the database or wait forever.
- **Tables:**
  - `meta`: `&str → &[u8]` holding `format_version` (`u32`, value 1) and `seed` (`u64`). On reopen, the stored seed **wins** over the config seed; return it so the server builds its generator from it, and log a mismatch once.
  - `block_states`: `u32 → &str` maps each on-disk id to a canonical state string, `namespace:path[prop=value,…]` with properties in declaration order. On open, build both remap tables, runtime ↔ disk. States missing from the table are appended with new ids in the same transaction. A stored name the registry lacks is `StorageError::UnknownBlockState(name)`; unknown-block placeholders come later.
  - `cubes`: 13-byte key `[kind: u8][x][y][z]`, each coordinate an `i32` big-endian with the sign bit flipped so keys sort by coordinate. `kind = 0` is a LOD0 cube; reserve and document the others (LOD cubes come in 2.7). Value: `[record schema u8 = 1][zstd frame of the codec bytes]`, at zstd level 3.
- **API:**
  - `load(pos) -> Result<Option<Cube>, StorageError>`.
  - `save_batch(&[(CubePos, &Cube)]) -> Result<(), StorageError>`: one write transaction, committed with redb's immediate durability. When it returns, the batch is on disk.
  - `cube_count()`.
- **Errors are typed:** `Io`, `Locked`, `Corrupt { pos, reason }`, `UnknownBlockState`, `VersionTooNew`.

### Server integration (`server.rs`, `gen_pool.rs`, `run.rs`)

**Config:**
- `ServerConfig` gains `world_dir: Option<PathBuf>` and `save_interval: Duration`.
- `None` means no persistence and exactly today's behavior. Pinned cubes then grow forever, as now, and every existing test keeps passing unchanged.
- Default: `None`, with `save_interval` 5 s. `protocol_only()` stays `None`.

**Construction:** `Server::try_with_config(config) -> Result<Server, StorageError>` opens storage first, so the stored seed feeds the generator. `with_config` becomes `try_with_config(..).expect(..)`, with a doc line saying so.

**Loading:**
- The gen pool becomes **load-or-generate**. Workers, and the inline path, call `storage.load(pos)` first and fall back to `generator.generate(pos)`.
- Keep the deterministic inline mode.
- Collection still uses `or_insert`, so a loaded or generated copy never overwrites a cube already in the world. Keep that comment.
- A `Corrupt` record is logged with its position, and the cube is generated instead. The record stays on disk untouched unless the cube is edited and saved again.

**Dirty tracking:**
- Each world cube has an **edit version**, a `u64` bumped by every accepted edit.
- With persistence on, a cube is pinned while `version > saved_version`. That covers both unsaved cubes and cubes in a save batch that has not committed yet.
- Eviction keeps pinned cubes, as now, and evicts everything else outside every keep set. Replace the 1.7 comment with the new rule.

**Background saver:**
- One thread, `jbm-save`, owns the write side.
- Every `save_interval`, the tick thread takes a **snapshot**: a clone of each pinned cube whose current version has not already been sent, together with that version. It sends the snapshot as one batch over a channel.
- The saver encodes, compresses and commits one transaction per batch, then replies with `(pos, version)` acknowledgements.
- The tick thread applies the acknowledgements at the start of the streaming phase: `saved_version = max(saved_version, acked)`. An edit made after the snapshot keeps the cube pinned until the next batch.
- The tick thread **never** compresses, encodes or waits on disk I/O during normal ticks.
- A failed save is logged, and its cubes stay pinned and are retried next interval. Never drop edits silently.

**Shutdown:**
- `Server` gains a synchronous `flush()`: send everything still pinned, then wait for its acknowledgement.
- `Drop for Server` calls `flush()`, closes the channel and joins `jbm-save`.
- `ServerHandle::stop` and `Drop` therefore persist all edits.
- **Test accessors:** `dirty_count()`, `pending_save_count()`, `saved_batches()`.

### Game binary (`crates/game/src/main.rs`)

- The world directory is `saves/default` under the current directory. `JBM_WORLD_DIR` overrides it, and `JBM_NO_SAVE=1` disables persistence.
- A `Locked` or other storage error prints a one-line message and exits non-zero; no panic.
- Add `/saves` to `.gitignore`.

## Tests

**Core:**
- Round trips, as above.
- **Decode fuzz:** 10,000 seeded random byte strings, every truncation of a valid encoding, and 1,000 single-byte mutations of valid encodings. Each returns `Err` or a valid cube; nothing panics.

**Storage unit tests**, in temp dirs:
- Save then load equals the original.
- A missing cube returns `None`.
- Reopen keeps cubes and seed.
- Second open returns `Locked`.
- Key ordering holds across negative coordinates.
- **Remap:** write with registry A, then reopen with registry B, which registers the same blocks in a different order. Cubes decode to the same block names.
- A stored state unknown to the registry returns `UnknownBlockState`.
- A corrupt value (bytes overwritten through a raw redb write) returns `Corrupt` from `load`, and the server path regenerates instead of crashing.

**Server and testkit integration** (`crates/testkit/tests/persistence.rs`):
- **Survives restart:**
  1. Inline gen, a temp world dir.
  2. Place and break a few blocks.
  3. Drop the server, which flushes.
  4. Start a new server on the same dir.
  5. A player joins and receives `CubeData` containing the edits.
- **Unpin after save:** edit, step past `save_interval`, then walk away. The edited cube is evicted (`world_cube_count` drops, `pinned_count` is 0). Walk back, and the cube streams in from disk with the edit, not regenerated without it.
- **Edit during save:** snapshot, edit the same cube before the acknowledgement, apply the acknowledgement. The cube stays pinned until the second batch commits. To make it deterministic, use a test hook that holds the saver.
- A save failure keeps cubes pinned; inject it through a test hook.
- `world_dir: None` behaves exactly as before: the existing pinned tests pass untouched.

**Kill during save** (`crates/testkit/tests/kill_during_save.rs`, in testkit so the server-level part can use `TestClient`; do not make jbm-server dev-depend on testkit), the acceptance core:
- The test re-executes its own binary (`std::env::current_exe()` with `--exact <child test> --nocapture`) as a child process gated by an environment variable.
- **Storage level:**
  - The child loops forever on batch `k = 1, 2, …`. Each batch rewrites the same 64 cubes, each filled with a pattern derived from `k` and the cube's position, and stores `last_batch = k` in `meta` within the same transaction.
  - The parent waits for the child's "started" line, waits a seeded random 20–400 ms, then kills it with `Child::kill` (SIGKILL on unix), for 10 rounds on the same directory.
  - After each kill, the parent opens the database and checks:
    - it opens, with no `Locked` error left behind
    - all 64 cubes decode
    - every cube shows the same `k`
    - `k == last_batch`
- **Server level:**
  - The child runs a real `Server` with `save_interval` of 50 ms and one testkit client that places one block per tick along a line.
  - The parent kills it at a random time, then opens a fresh `Server` on the directory.
  - The placed blocks must be a **prefix** of the placement sequence: block i present implies every block before i is present. Every stored cube must load.
- Mark the test `#[cfg(unix)]` if `Child::kill` semantics demand it; CI runs macOS and Ubuntu.
- Run it 5 times locally; it is never flaky.
