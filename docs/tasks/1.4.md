# 1.4 Greedy mesher, worker pool, packed faces, vertex pulling, game wiring

**Goal:** the client turns cubes into GPU meshes and draws them. A greedy mesher runs on a worker pool and emits 8-byte packed faces. The vertex shader pulls faces from a storage buffer and expands each into a quad, with no vertex buffer. The client keeps a world of cubes received from the server and re-meshes cubes when they or their neighbors change. `jbm-game` now starts the server thread and the client connects to it over `in_process_pair`.

**Read:**
- CLAUDE.md, and the READMEs of crates/core, crates/client and crates/game.
- docs/design.md "Rendering" and "World representation".
- `crates/core/src/protocol.rs`. `ServerMsg::CubeData`, `ServerMsg::UnloadCube` and `Welcome { spawn }` already exist on main.

**Parallel work:** task 1.5 builds terrain generation and cube streaming on the server at the same time. Until it merges, `Server::new()` sends no cubes. Your tests must build their own cubes and must not depend on server terrain.

## Scope (`jbm-client`, plus `jbm-game` main)

No new dependencies. Threads come from `std`.

### Block appearance table (`mesh/appearance.rs`)

- `BlockAppearance` is built once from the `BlockRegistry` and the builtin `Blocks`, then shared read-only (`Arc`) with the mesh workers. The hot path never calls `registry.info()` or does string lookups.
- It is a flat table indexed by `BlockStateId.0`. For each state it holds:
  - a flags byte: air, opaque, cutout
  - 6 texture layers (`u16`), one per face direction
- Mapping for the builtin blocks:
  - grass_block: grass top, grass side on the four sides, dirt on the bottom
  - oak_log: log top on the two faces along its `axis`, log side elsewhere, for all three axis states
  - glass and leaves: cutout
  - water: opaque blue for now. Translucency is a later task; leave a TODO in the README.
- `builtin_textures() -> (Vec<RgbaImage>, layer names)`: procedural 16×16 placeholders.
  - One layer each for: stone, dirt, grass_top, grass_side, sand, water, glass, oak_planks, oak_log_side, oak_log_top, leaves.
  - Use a small deterministic hash for per-pixel noise. Distinct colors make each block recognizable in screenshots.
  - glass and leaves have pixels with alpha exactly 0 or 255.
- Replace the use of `placeholder_layers` in the app with these. Keep `placeholder_layers` for its existing tests.

### Packed face format (`mesh/face.rs`)

`#[repr(C)] PackedFace(u32, u32)` derives `Pod` and `Zeroable`. It is 8 bytes: a test asserts `size_of == 8`.

**Word 0:**

| bits | field |
|---|---|
| 0..5 | x |
| 5..10 | y |
| 10..15 | z |
| 15..20 | width − 1 |
| 20..25 | height − 1 |
| 25..28 | direction (0 +X, 1 −X, 2 +Y, 3 −Y, 4 +Z, 5 −Z) |
| 28..32 | spare, zero |

**Word 1:**

| bits | field |
|---|---|
| 0..16 | texture layer |
| 16..24 | AO, 2 bits per corner, corners in a fixed documented order |
| 24..28 | light 0–15 (always 15 until lighting exists) |
| 28..32 | spare, zero |

- (x, y, z) is the block that owns the face, in cube-local coordinates.
- Width and height run along the face's two in-plane axes. Choose them per direction, document the (u, v) axes for each direction in the README, and use them identically in Rust and WGSL.
- Add `pack`/`unpack` with a round-trip test over the edge values.
- WGSL decodes the same bits. Keep the layout in one comment block that both files reference.

### Mesher (`mesh/greedy.rs`, pure logic, no GPU)

**Input** is a `MeshInput`:
- the center cube as `Arc<Cube>`
- 26 neighbors as `Option<Arc<Cube>>`, indexed by offset

The mesher first builds a padded 34³ array of state ids from them:
- Use `Cube::iter()` for the center and bulk loops for the borders. Never call per-block `get` in the inner loop: `iter()` is about 3× faster.
- `Cube::uniform()` fast paths:
  - A uniform air center gives zero faces without building anything.
  - A uniform opaque center whose 6 face neighbors are all present and uniform opaque gives zero faces.

**Face rule.** A face of block A toward neighbor B is emitted when:
- A is not air, and
- B is not opaque, and
- not (A == B and A is cutout), so glass-glass and leaves-leaves interiors are culled.

A missing neighbor cube counts as **opaque** for this rule, so there are no walls facing unloaded space. For AO it counts as **air**.

**AO** is per corner, 0–3, using the classic side1/side2/corner rule:
- `if side1 && side2 { 0 } else { 3 - (side1 + side2 + corner) }`
- Opaque blocks occlude. Cutout and air do not.

**Greedy merge:**
- Per direction and per slice, merge coplanar faces with identical (texture layer, AO pattern, light) into maximal rectangles: first along u, then extend along v.
- Faces never span outside the cube.
- A bitmask approach (one `u32` per row, since rows are 32 wide) is encouraged but not required.

**Output:** `MeshOutput { faces: Vec<PackedFace>, ranges: [Range<u32>; 6] }`, with faces grouped by direction so 2.2 can skip back-facing directions.

**Tests:**
- A single stone block with air neighbors gives 6 faces of size 1×1.
- A 2×2×2 stone block gives 6 faces of 2×2.
- A full stone cube gives:
  - 0 faces when all 26 neighbors are missing
  - 6 faces of 32×32 when all 26 neighbors are air
- The checkerboard worst case gives 16384 × 6 faces.
- Glass next to glass shares no inner face. Stone next to glass does show the stone face.
- An L-shaped corner shows AO values below 3 on the expected corners.
- A block on the cube border with a neighbor cube present: there is no face toward a solid block in the neighbor, and AO reads the neighbor.
- **Property test** (local xorshift, 200 random cubes with random neighbors, a mix of air, stone, dirt and glass):
  - Rasterize the greedy output back into unit faces.
  - It must equal the set produced by a naive one-face-per-block mesher written in the test.
  - No two output faces may overlap.

### Worker pool (`mesh/pool.rs`)

- `MeshPool::new(threads)`:
  - Defaults to `available_parallelism() - 2`, minimum 1.
  - Named threads `"jbm-mesh-N"`.
  - The job queue is a `Mutex<mpsc::Receiver>` or similar. Results come back on an mpsc.
- `submit(pos, version, MeshInput)` and `try_recv() -> Option<MeshResult>`, non-blocking.
- Each job carries a per-cube `version`. The client world drops any result older than the cube's latest version.
- Dropping the pool closes the queue and joins every thread. It must never detach, and must never hang if a job is in flight.
- A worker panic must not be silently swallowed: the next `try_recv` surfaces it as an error or panics with the message.
- **Tests:**
  - 1000 jobs all come back, with the same output as calling the mesher directly.
  - Stale versions are droppable.
  - Dropping the pool with jobs queued returns promptly (under 2 s, bounded wait).

### Client world (`world.rs`, pure logic, no GPU)

- `ClientWorld` holds `HashMap<CubePos, Arc<Cube>>`, a dirty set and per-cube versions.
- `apply(&ServerMsg)`:
  - `CubeData`: insert or replace the cube, and mark it and its 26 loaded neighbors dirty.
  - `UnloadCube`: remove it and its mesh. Do not re-mesh its neighbors.
- `take_dirty(budget) -> Vec<(CubePos, u32 version, MeshInput)>` returns the dirty cubes nearest to the camera first, up to `budget` per call.
- **Tests:**
  - A neighbor arriving re-dirties the cubes next to it.
  - Unload removes the cube.
  - Versions increase.
  - Ordering is nearest-first.

### GPU side (`render/chunks.rs` or similar)

**Per meshed cube:**
- one storage buffer of `PackedFace`s
- a draw of `face_count × 6` vertices, with no index buffer or a shared static one
- empty meshes allocate nothing

Re-meshing a cube replaces its buffer. A suballocator and multi-draw indirect come in 2.2; keep the draw loop simple. No per-frame buffer creation: per-cube origins go in one buffer that is rewritten each frame.

**Camera-relative origins:**
- Each frame, compute `cube_min_world - camera.position` in f64 and cast to f32 (`Camera::relative`), and give it to the shader per draw: for example an origins storage buffer indexed by `instance_index` with `first_instance = slot`, or a dynamic uniform offset.
- Never put absolute world coordinates in f32 anywhere.

**Upload budget:** at most N mesh uploads per frame (default 32), so streaming never hitches a frame.

**CPU frustum culling** of cube AABBs, using the camera-relative frustum.

**Terrain pipeline:**
- Depth `Greater` with the reverse-Z invariants.
- Back-face culling on.
- Samples `BlockTextures` with the existing sampler.
- `discard` where alpha < 0.5.
- Simple directional shading per face direction (top 1.0, sides 0.8/0.6, bottom 0.5) times the AO factor.
- On a quad with AO, pick the triangle diagonal by AO to avoid anisotropy.

**Renderer integration:** `Renderer::render` draws the sky, then the terrain, then the overlay. Keep the sky and overlay goldens passing unchanged.

**Overlay:** add lines `CUBES <loaded> MESHED <n> PENDING <dirty+in flight>` and `FACES <total> DRAWS <n>`.

### App (`app.rs`) and game (`crates/game/src/main.rs`)

**`app::run(link: ClientLink)`:**
- Sends `Hello`. Waits for `Welcome` without blocking the event loop: poll the link every frame.
- On `Welcome`, moves the camera to `spawn`.
- Each frame:
  - Drain the link into `ClientWorld`, with no cap on messages but bounded work per message.
  - Submit dirty cubes to the pool, up to a per-frame budget.
  - Receive finished meshes and upload them within the upload budget.
- Sends `PlayerInput` with the camera position at most 20 times per second.
- `Rejected`, `Disconnected` or a closed link prints the reason to stderr and exits the loop cleanly.

**Game `main`:**
- Spawn `jbm_server::run::spawn(Server::new())`, make `in_process_pair()`, `handle.connect(server_end)`, then call `jbm_client::app::run(client_end)`.
- When the window closes, call `handle.stop()`. The server thread must never be detached.

Keep the wave A redraw/occlusion handling in app.rs exactly as it is. It fixed a real macOS bug; see `docs/progress.md` "Known issues".
