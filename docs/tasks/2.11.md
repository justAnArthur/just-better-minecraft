# 2.11 Code review and restructuring (no behavior change)

**Goal:** clean module structure before wave E's features land:
- 2.12 a playground with an egui debug panel;
- 2.13 meshing optimization and a larger full-detail radius;
- 2.14 height-exact LOD.

Every step **moves, merges or deletes code without changing behavior**. Goldens, test outcomes, wire formats, stored data and benchmark medians (within ±15% noise) stay the same.

The orchestrator's structure review found sound crate boundaries. `core` is pure, `Link` is respected, and the hard rules each live in one place. Inside the crates it found:
- two god files;
- one client pipeline written four times;
- surface rules duplicated between `generate` and `sample_lod`;
- copy-pasted test fixtures;
- no seams for the debug panel.

The findings are below; line numbers are as of `stage-2/wave-d` @ 5944ac9.

## Rules for every step

- **No behavior change.** If a move tempts a fix, write it in the report as a follow-up; do not do it. The only allowed exceptions are the ones a finding names explicitly (e.g. deleting a stub).
- **Run GPU tests for real:** `JBM_REQUIRE_GPU=1 cargo test --workspace`. Without it the screenshot tests skip silently and prove nothing.
- **Gates for every step:**
  - `cargo fmt --all --check`;
  - `cargo clippy --workspace --all-targets -- -D warnings`;
  - `JBM_REQUIRE_GPU=1 cargo test --workspace`;
  - `cargo bench --workspace -- --test`.
- **Bench medians:** before and after for the benches covering the moved code (named per step). Compare them in the same session.
- **Goldens:** `git diff --stat <base> -- '*/tests/golden'` must be empty.
- **Comments:** while moving a file, rewrite task-number references ("task 2.6", "pre-2.8") as plain explanations. The history lives in docs/progress.md.
- **READMEs:** update every README whose module map changes.
- **Commits:** scoped Conventional Commits; `refactor(<crates>): …` for moves.

### 2.11a Server worldgen: shared surface rules, noise out of `reference` (findings F3, F6)

**F3.** Surface and material rules are duplicated in `server/src/terrain.rs`:
- `column_material` (`:120-129`) is re-implemented inline at `:846-866`; the only difference is that the slope bar there is `× step`.
- The 4-neighbour slope is computed twice (`:594-603`, `:850-856`).
- `generate` (`:528-692`) and `sample_lod` (`:694-922`) each own a copy of the downward `d`-run fill loop.

Turn the file into `server/src/terrain/`:
- `mod.rs`: `Generator`, the column cache, `surface_height`, `spawn`.
- `surface.rs`:
  - `surface_block`, `surface_block_sea`, `TopMaterial`;
  - `column_material(h, slope, step)` (at `step = 1` it is today's rule exactly);
  - `max_neighbor_step(grid, stride, x, z)`;
  - one `style_column(...)` loop that both callers use.
- `lod_sample.rs`: `sample_lod`, split into named phases (sample columns → style → reduce). This is the seam 2.14 replaces.

**F6.** `worldgen::reference` is half production code.
- Its noise primitives (`reference.rs:43-410`: `GRADIENTS`, `noise2`, `fbm`, `ridged2`) are called at runtime by `graph.rs:1554-1570`. Move them to `worldgen/noise.rs`.
- Gate what is left (`height`, `column_block`, `ReferenceGenerator`, `:419-552`) behind a `reference` cargo feature, enabled through a self dev-dependency. This is the pattern `jbm-client` uses for `testing`, so the equivalence test and `worldgen_bench` keep it.
- Do not delete it: `Preset::Classic` pins goldens.

**Verify:**
- `worldgen_equivalence`;
- the level-1 exactness tests in `server/tests/lod.rs` (around `:1248` and `:1309`);
- `server/tests/overworld.rs`;
- `worldgen_bench` and `lod_bench` medians.

### 2.11b Server split (F4)

`server/src/server.rs` mixes five concerns:
- config (`:108-200`);
- a 30-field `Server` (`:344-420`) with about 20 test-only accessors (`:566-803`);
- edits (`:1044-1140`);
- persistence (`:1151-1352`, plus `save_loop` at `:2028`);
- streaming (`:1451-1994`);
- unit tests (`:2066-3490`).

The pure helpers sit in `streaming.rs`, while the streaming itself is in `server.rs`. Turn it into `server/src/server/`:
- `mod.rs`: `Server`, `tick`, the message phases.
- `config.rs`.
- `edits.rs`.
- `persist.rs`: `SaveBatch`, `SaveAck`, `phase_save`, acks, `flush`, `save_loop`.
- `stream.rs`: `phase_streaming`, `stream_player`, `stream_player_lod`, the keep helpers.
- `stream_plan.rs`: today's `streaming.rs`. Its `#[cfg(test)] lod_walk` moves into the tests.
- `stats.rs`: a `ServerStats` snapshot struct and `Server::stats()`, replacing most test-only accessors (keep the ones tests need for things a snapshot can't express). The 2.12 panel reads this snapshot.
- The unit tests are split per submodule.

Keep the public paths that other crates use. If `jbm_server::server::Server` moves, re-export it.

Optional second commit: nest the six `lod_*` fields and `max_column_cubes` as `lod: LodConfig`. There are 49 `ServerConfig {}` literals in 19 files. Do it only if the first commit is green, and keep it a pure rename.

**Verify:**
- the whole server and testkit suites;

### 2.11c Render split and `RenderSettings` (F2)

`client/src/render/chunks.rs` (2975 lines) mixes:
- GPU layouts (`:62-260`);
- frustum and camera math (`:570-697`);
- stats and the readback ring (`:699-880`);
- page bookkeeping (`:331-560`);
- a 426-line `build` (`:1031-1457`);
- both draw paths: gpu-cull `:2034-2230`, cpu-cull `:2290-2445`.

Turn it into `render/terrain/`:
- `mod.rs`: the public `TerrainPass` API.
- `layout.rs`: `CubeMeta`, `TerrainUniforms`, `CullParams`, the meta flags, the tint/fog/AO constants, and the WGSL layout tests.
- `space.rs`: `camera_split`, `cube_origin`, `Frustum`, `visible_directions`, `cube_size`.
- `pages.rs`: `FacePage`, `MeshBookkeeping`, `Released`.
- `stats.rs`: `TerrainStats`, `LevelStats`, `CullStats`, `StatsRing`.
- `pipelines.rs`: `build` and the bind groups.
- `cpu_cull.rs`, `gpu_cull.rs`.

Fog and LOD-tint state is duplicated in `Renderer` (`renderer.rs:331-351`) and `TerrainPass` (`chunks.rs:1820-1835`). Environment variables are read inside constructors:
- `renderer.rs:321` `JBM_NO_FOG`;
- `chunks.rs:1378` and `:1394` `JBM_NO_MDI` and `JBM_GPU_CULL`;
- `app.rs:292` `JBM_LOD_TINT`.

Add `render/settings.rs` with `RenderSettings { fog, lod_tint, force_cpu_cull, prefer_gpu_cull, force_fallback, far_radii, … }` and `RenderSettings::from_env()`, read once by the app.
- The renderer owns one copy and passes `&RenderSettings` to `TerrainPass::draw`.
- Existing setters (`set_fog`, `set_lod_tint`, `set_force_*`) stay as thin wrappers so tests don't churn.
- 2.12 adds wireframe, chunk borders, exploded view, a per-level mask and freeze-cull as fields here.

**Verify:**
- every client and game screenshot golden;
- the path-identity tests (`terrain_paths`, `lod_rings`);
- the `terrain_draw` medians on all three paths.
