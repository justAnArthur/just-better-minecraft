# 1.2 Window, wgpu surface, fly camera, texture array, debug overlay

**Goal:** `cargo run -p jbm-game` opens a window showing a sky. You can fly around with the mouse and WASD, and a debug overlay shows FPS and position. The renderer draws into any target (window surface or offscreen), so every later feature gets screenshot tests.

**Read:** CLAUDE.md, crates/client/README.md, crates/game/README.md, docs/design.md "Rendering" and "LOD system" (context: very far view distances).

## Dependencies

Add each to `[workspace.dependencies]` at the latest stable version:

- `winit` 0.30.x. Do not use the 0.31 betas.
- `glam`.
- `bytemuck` with `derive`.
- `font8x8`. It is public domain, so we use it instead of shipping our own font.

Do not add wgpu-version-coupled crates such as glyphon or egui-wgpu.

**wgpu is 30.0.1.** Its API differs from older tutorials. Check the real signatures in `~/.cargo/registry/src/*/wgpu-30.0.1/` and `crates/client/src/gpu.rs`. Known quirks:

- `request_adapter` returns a `Result`.
- `InstanceDescriptor` has new constructors.
- Readback rows align to `wgpu::COPY_BYTES_PER_ROW_ALIGNMENT`.
- Polling uses `PollType::Wait { .. }`.

## Scope (`jbm-client`, plus a small `jbm-game` main)

### Camera (`camera.rs`, pure math, unit-tested)

- `Camera`:
  - `position: glam::DVec3`, in f64 because world coordinates reach about 6.8·10¹⁰
  - `yaw` and `pitch: f32` in radians, with pitch clamped to ±89°
  - `fov_y`
  - `aspect`
- Yaw 0 looks toward −Z, and +Y is up.
- Projection is **reverse-Z, infinite far plane**:
  - near = 0.05
  - depth format `Depth32Float`
  - clear depth 0.0
  - compare function `Greater`
  - This is for Stage 2's kilometre view distances. Document it in the README as an invariant.
- **Camera-relative rendering:**
  - `view_proj()` is built with the camera at the origin, rotation only, and returned as `glam::Mat4` (f32).
  - Geometry is later offset by `(world_pos - camera.position)` computed in f64, then cast to f32.
  - Expose `fn relative(&self, world: DVec3) -> Vec3`.
- `forward()`, `right()`.
- **Tests:**
  - yaw/pitch → forward vectors
  - pitch clamp
  - a point straight ahead projects to the screen center
  - a nearer point gets the larger depth (reverse-Z)
  - `relative` keeps sub-millimetre precision at x = 10⁹

### Fly controller (`input.rs`, pure logic, unit-tested)

- `InputState` holds:
  - held keys as an enum, not winit types: Forward, Back, Left, Right, Up, Down, Sprint
  - accumulated mouse delta
- `FlyController { speed, sprint_multiplier, sensitivity }` and `update(&mut Camera, &InputState, dt: f32)`:
  - Horizontal movement follows yaw only.
  - Up and down move along world Y.
  - Diagonal movement is normalized.
  - Mouse delta is consumed.
- The winit → `InputState` mapping lives in the app layer:
  - WASD to move, Space for Up, Shift for Down, Ctrl to sprint.
  - Mouse motion comes from `DeviceEvent::MouseMotion` while the cursor is grabbed.
- **Tests:** one second of Forward at yaw 0 moves `speed` toward −Z; diagonal movement keeps the same speed; sprint multiplies the speed.

### Renderer (`render/` module)

- `Renderer::new(&Gpu, color_format) -> Renderer`. Pipelines are created per format, so the window (usually `Bgra8UnormSrgb`) and offscreen (`Rgba8UnormSrgb`) both work.
- `Renderer::render(&mut self, &Gpu, target: &wgpu::TextureView, depth: &wgpu::TextureView, camera: &Camera, overlay: Option<&OverlayText>)`.
- **Uniform buffer:**
  - holds the view-proj matrix, its inverse, the camera position as f32 hi/lo pairs (for later), and the sky colors
  - one `#[repr(C)]` bytemuck struct with a WGSL mirror
  - a test asserts the struct size matches the WGSL layout: 16-byte alignment, no hidden padding
- **Sky pass:**
  - A fullscreen triangle with no vertex buffers.
  - The fragment shader reconstructs the view ray from the inverse view-proj.
  - Color is a vertical gradient: horizon color, then zenith color, and below the horizon a darker ground-haze color.
  - The constants are in the uniform. Pick pleasant colors and write them down in the README.
  - It does not write depth. The depth attachment is cleared to 0.0 in the same pass so later passes can use it.
- `DepthTarget::new(&device, w, h)` with resize support.

### Texture array (`render/texture_array.rs`)

- `BlockTextures::new(&Gpu, layers: &[RgbaImage]) -> Result<Self, TextureError>`.
  - All layers must be the same square power-of-two size, otherwise return an error.
  - Mipmaps are generated on the CPU with a 2×2 box filter in linear space (sRGB → linear → sRGB) down to 1×1.
  - Uses one `D2Array` texture, `Rgba8UnormSrgb`.
  - Sampler: nearest mag, nearest min, linear mipmap filter.
  - Exposes `view()`, `sampler()`, `layer_count()`.
  - Respects `max_texture_array_layers` from the device limits, and errors out instead of panicking.
- `placeholder_layers(n) -> Vec<RgbaImage>`: generated 16×16 test textures, each a distinct color with a 1-pixel darker border and a diagonal mark so orientation is visible. No external assets.
- Nothing samples it yet; the mesher in 1.4 will.
- **Tests (GPU, via `gpu_or_skip`):**
  - Build 4 layers and read back layer 2, mip 0. Bytes must match the input exactly.
  - Read back mip 1 and check it against a CPU box filter within ±1.
  - Mismatched sizes give an error.

### Debug overlay (`render/overlay.rs`)

- A small text renderer using `font8x8` glyphs:
  - Build an R8 glyph atlas texture for ASCII 32..127 once.
  - Draw instanced screen-space quads from a per-frame instance buffer.
  - Scale is an integer (2× by default).
  - White text on a semi-transparent dark background box behind each line. Alpha blending is on.
- `OverlayText` is a list of lines.
- The app fills it with:
  - `FPS <n>  <frame ms>`
  - `XYZ <x> <y> <z>` with 2 decimals
  - `CUBE <cx> <cy> <cz>`
  - `YAW <deg> PITCH <deg>`
- `FrameStats` is pure logic: average FPS and frame ms over a sliding 0.5 s window. Unit-test it with synthetic frame times.

### App and window (`app.rs`)

- `pub fn run() -> Result<(), ...>` uses winit 0.30's `ApplicationHandler`.
  - It creates the window (1280×720, title "just-better-minecraft") and the surface.
  - The surface prefers an sRGB format, and the present mode is `AutoVsync`. With `JBM_VSYNC=0` it is `AutoNoVsync`.
  - Handles resize (reconfigure the surface and depth; ignore 0×0 while minimized), `SurfaceError::Lost/Outdated` (reconfigure) and close.
- Input:
  - Left click grabs and hides the cursor. Try `CursorGrabMode::Locked`, then fall back to `Confined`.
  - Esc releases the cursor. A second Esc while released quits.
- `Gpu` gains a constructor that takes a surface (`Gpu::for_surface`). Keep `Gpu::headless()` unchanged for tests.
- Spawn position is (0, 80, 0).
- `jbm-game` `main` calls `jbm_client::app::run()`. No server yet: task 1.3 builds it in parallel, and wiring them together comes in wave B.

### Fix a known issue

`render/offscreen.rs` `read_rgba`: a device poll failure must panic in release builds too (with the error message), not hang on `recv()`. Replace the `debug_assert`.

## Screenshot tests (`crates/client/tests/screenshot.rs`, 256×256, keep `triangle`)

Each golden scene uses an exact camera, written in the test:

- `sky_horizon`: camera at (0, 80, 0), yaw 0, pitch 0, fov 70°. The horizon line runs across the middle.
- `sky_up`: pitch +60°, so the image is mostly zenith color.
- `sky_down`: pitch −60°, so the ground haze shows.
- `debug_overlay`: the sky_horizon scene plus a fixed `OverlayText` (`"FPS 60  16.67 ms"`, `"XYZ 0.00 80.00 0.00"`). Fixed text, never live FPS.

Generate goldens with `JBM_UPDATE_GOLDEN=1 cargo test -p jbm-client --test screenshot`; this exact command is allowed in your sandbox. Look at each PNG before committing and describe in the report what each one shows.

## Acceptance

- `cargo test --workspace` passes, and the screenshot tests run instead of skipping on this Mac. fmt and clippy `-D warnings` pass. `cargo bench --workspace -- --test` passes.
- `cargo build -p jbm-game` succeeds. You probably cannot open a window in your sandbox. Say whether you could run it, and if you could not, do not fake it.
- `cargo tree -p jbm-client` contains no `jbm-server`.
- crates/client/README.md documents:
  - the modules
  - reverse-Z and camera-relative rendering, as invariants
  - the uniform layout rule
  - the controls
  - the overlay
