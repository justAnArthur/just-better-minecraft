# 2.1 Declarative worldgen: density graph and native evaluator

**Goal:** terrain shape becomes data. A JSON density-function graph describes it, and a native evaluator compiles that graph once and samples it at any resolution. The 1.5 terrain (`terrain.rs`) is re-expressed as the shipped graph `overworld.json`, and the result must be **bit-identical**: every cube, every surface height, both existing goldens unchanged. Sampling at a 2ⁿ step is the entry point later LOD tasks (2.4, 2.7) build on, so it is benchmarked here at several resolutions.

## Scope

### Public API stays put (`jbm-server::terrain`)

`Generator` keeps exactly its current public surface, so no caller changes: `Generator::new(seed, blocks)`, `generate(pos) -> Cube`, `surface_height(x, z) -> i64`, `spawn() -> [f64; 3]`, and the `MIN_HEIGHT` / `MAX_HEIGHT` consts. It must stay `Send + Sync` (the gen pool shares it in an `Arc`). Internally it now runs the compiled shipped graph.

Add `Generator::from_graph(seed, blocks, graph: &CompiledGraph)` (or similar) so tests and later mods can supply another graph.

### Graph format (new module `crates/server/src/worldgen/`)

- **Format: JSON, via `serde` (derive) and `serde_json`.** These are the only new dependencies; pin exact versions in `[workspace.dependencies]`.
- **Top level:**
  - `version: 1`.
  - `nodes`: a map of named nodes.
  - `outputs`: at least `final_density`.
- **Nodes and references:** a node is either an inline object (`{"type": "add", "a": …, "b": …}`), a number literal (constant), or a reference to a named node (`{"ref": "hills"}`). Named nodes let a graph share subexpressions; the compiler evaluates each shared node once per sample, not once per use.
- **Node set** (all `f64`):
  - `x`, `y`, `z`: block coordinates of the sample.
  - Constants, `add`, `sub`, `mul`, `neg`, `min`, `max`, `abs`, `floor`, `clamp { input, min, max }`.
  - `noise2 { salt, x_scale, z_scale }`: the existing 2D gradient noise at `(x·x_scale, z·z_scale)`, seeded with `world_seed ^ salt`.
  - `fbm2 { salt, scale, octaves }`: the existing fractal sum, at `(x·scale, z·scale)`.
  - `spline { input, points: [[x, y], …] }`: piecewise linear, clamped at both ends, points strictly increasing in x.
  - Integers above 2⁵³ (salts) must round-trip exactly: write `salt` as a hex string such as `"0x0D1B54A32D168ED5"`, not a JSON number.
- **Errors:** a malformed graph returns a typed error that names the offending node path. Errors include unknown type, missing field, dangling ref, cycle, bad spline, unknown version and missing `final_density`. Loading never panics on bad input.
- **Determinism rule:** keep it from `terrain.rs` and restate it in the module docs: only `+ - * floor`, comparisons and integer hashing. No `sin`, `cos`, `exp` or `powf` in any node. `spline` uses only `+ - * /`; division is IEEE-exact too, so say so.

### Density semantics and the surface stage

- A cell is **solid** when `final_density ≥ 0`. Solid cells are stone before the surface stage.
- **Surface stage** (code, not graph, for now): for a solid cell at `y`, let `d` be the number of consecutive solid cells directly above it, capped at 4, so `d = 0` means the cell above is air. Then:
  - If `d ≤ 3` and the surface `y + d` is at or below 61 (`SAND_LEVEL`): sand.
  - Else if `d = 0`: grass.
  - Else if `d ≤ 3`: dirt.
  - Else: stone.

  For a pure heightmap density this is exactly today's `column_block`. Show the equivalence in a comment. Computing `d` for the top rows of a cube needs density for up to 4 cells above the cube; evaluate them, never peek at neighbor cubes.
- **The shipped graph** `crates/server/assets/worldgen/overworld.json`, embedded with `include_str!`, expresses `final_density = (64 + floor(clamp(40 · hilliness · rolling, -28, 28) + 0.5)) - y`, where `hilliness` and `rolling` are today's mask and fbm with today's salts and frequencies.
  - Operand **association** must match `terrain.rs` exactly, or the floats differ. For example, `(40 · hilliness) · rolling`, not `40 · (hilliness · rolling)`.
  - Commutation is safe; association is not. Note this in the JSON's neighboring README section.

### Compiler and evaluator

- `compile(&Graph) -> Result<CompiledGraph, GraphError>` flattens the DAG into a topologically ordered instruction list in a register array: no recursion and no allocation per sample.
- **Dimension analysis:** tag each instruction constant, xz-only or xyz.
  - Constants fold at compile time.
  - The evaluator runs the xz-only instructions **once per column** and the xyz rest per cell.
  - This is what keeps 3D evaluation near heightmap cost; the shipped graph's only xyz work is `- y`.
- **Interval bounds:** `CompiledGraph::bounds(aabb) -> (min, max)` by interval arithmetic.
  - Noise nodes report their documented range: `noise2` within ±√2/2, `fbm2` the same after normalization. Justify both in a comment.
  - `Generator::generate` uses bounds for the uniform fast paths. Max below 0 over the cube means air. Min at or above 0 over the cube extended 4 cells up means stone.
  - The fast paths may differ from today's per-column check, but the produced cubes must not.
  - `MIN_HEIGHT` / `MAX_HEIGHT` stay the documented bounds. A test checks that `bounds` of the shipped graph proves them: density < 0 for every y > 92 and ≥ 0 for every y < 36.
- **Sampling API**, for LOD and benches: `CompiledGraph::sample_grid(seed, origin: [i64; 3], step: u32, out: &mut [f64; 32*32*32])`.
  - It fills a 32³ grid of densities at `origin + step · (i, j, k)`, with `step` a power of two from 1 to 64.
  - Layout `(k * 32 + j) * 32 + i` over `(x = i, y = j, z = k)`; document it.
  - Step 1 at a cube origin gives exactly the densities `generate` uses.
- **Caching:** keep a bounded per-column cache equivalent to today's heightmap cache, holding the xz-stage results for the 32² columns of a cube column, so vertically adjacent cubes don't recompute noise. Keep the "pure-function cache, cannot change answers" argument in its doc comment. Scratch buffers per call or per thread; no locks held during evaluation.
- `surface_height(x, z)`: the highest solid `y` within the graph's bounds, found from the column's xz stage plus a scan over y. Always within bounds for the shipped graph.

Move today's height function, gradients and noise into `worldgen/reference.rs`, `#[doc(hidden)] pub`, unchanged apart from moving. The graph nodes `noise2` and `fbm2` call the same noise functions; do not duplicate the gradient table. The reference generator exists for the equivalence tests and the comparison bench. ## Tests

**Equivalence**, the acceptance core, with exact equality only:
- Graph `generate` equals reference `generate` for every cube with x, z ∈ [-6, 6) and y ∈ [0, 4), for `DEFAULT_SEED` and two other seeds. The reference generator is the old terrain logic, kept for this test.
- Graph `surface_height` equals the reference over a 512×512 area (every block), plus 1,000 pseudo-random columns up to |x|, |z| ≈ 10⁹.
- `sample_grid` at step 1 equals the densities implied by those cubes: the sign matches solidity everywhere.
- Every existing terrain.rs test keeps passing unchanged; move them only if a module move forces it.
- Goldens `terrain_spawn` and `edit_spawn` pass **without regeneration**.

**Graph format:**
- Every error kind from "Errors" above, one test each, asserting the error names the node.
- Shared named nodes are evaluated once: count instructions, or use a test-only counter.
- Salts round-trip.
- A hand-written graph (`y - 70`, flat) yields a flat world with the right layering.
- A 3D graph with an overhang (a `spline` over y) shows that the surface stage puts grass on top of the overhang and stone under it.

**Evaluator:**
- Constant folding happens.
- xz-only instructions run once per column.
- `bounds` contains the actual sampled values over random boxes.
- `sample_grid` at steps 2, 4 and 8 equals point evaluation at the same coordinates.

## Benches (`crates/server/benches/worldgen_bench.rs`)

Keep the existing names; they now measure the graph generator:
- `worldgen/heightmap_32x32`
- `worldgen/surface_cube`
- `worldgen/air_cube`

Add:
- `worldgen/reference_surface_cube`: the old code, the baseline.
- `worldgen/sample_grid/{1,2,4,8,32}`: one 32³ `sample_grid` near the surface at each step. Step 32 covers 1,024 blocks, so it measures the worst-case cache miss.
- `worldgen/compile_overworld`.

**Report:** all medians, with `surface_cube` against `reference_surface_cube`. The graph may be at most **2×** slower than the reference on `surface_cube`. If it is slower than that, profile it and say why before finishing.
